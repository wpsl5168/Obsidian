# 大模型演进与主流架构体系

> [!note] 版本与证据边界
> 本页保留“原理 → 模型演进 → 训练范式 → 工程选型”的阅读结构，面向 .NET/SQL Server 开发者。2026-10-20 重核原文：纠正若干发布日期、无依据的参数量猜测与降本比例。下面是有来源的历史节点，不是当日完整模型榜单；历史更新日志记录曾经改过什么，不代表其中旧数字仍成立。

## 核心概念

大语言模型（Large Language Model, LLM）可看作一个条件概率函数：给定已有 Token，计算后续 Token 的概率分布。用 .NET 表达近似为 `Func<Token[], ProbabilityDistribution<Token>>`。生成文本时还要经过采样、停止条件和输出处理；概率最高的续写不等于经过事实核验的答案。

参数是训练得到的权重，不是能按主键查询的知识条目。可以用“宽表维度”帮助理解容量，但不能推导“参数越多，存储与计算指数级增加”：固定权重精度时，原始权重大小近似随参数量线性增长；计算还受序列长度、稀疏激活、注意力形式和硬件实现影响。

### Transformer 架构：一切的起点

2017 年《Attention Is All You Need》提出由 Encoder 与 Decoder 构成的 Transformer，用注意力替代循环/卷积作为序列建模的主要机制。[1] 标题中的“一切”是本教程的历史起点，不表示所有模型都只有 Transformer 一条路线。

- **Self-Attention**：从同一序列构建 Q/K/V，让当前位置读取允许访问的其他位置。Decoder 生成使用因果遮罩，Encoder 通常可读取输入的双向信息；不是所有 Attention 都只“回头看”。
- **Feed-Forward**：对每个位置的表示进行非线性变换。MoE 可以把这一部分替换为由路由器选择的专家网络。
- **残差连接**：把子层变换与原输入相加，改善信息和梯度传播；它不是异常发生后才启动的 `try-catch fallback`。
- **位置表示**：提供顺序信息。并行计算训练位置，不意味着自回归输出的所有位置能同时独立生成。

.NET 类比只用于区分职责：层堆叠有些像 Middleware Pipeline，但注意力权重、向量运算、训练梯度都没有对应的普通中间件行为。详细推导见 [[10-知识库/AI模型与Agent/01-基础架构与模型底座/1.1.1-Attention-Is-All-You-Need深度解读]]。

### 架构演化三条路线

- **Encoder-Only**：BERT、RoBERTa 是典型例子；适合分类、实体识别、表示学习。任务若只要有限标签，不必默认引入长文本生成循环。
- **Decoder-Only**：自回归生成文本/代码的常见路线；GPT、Llama 等系列可用于理解这一范式。某个商业系列的完整内部结构未公开时，不从产品名反推 Dense/MoE、层数或参数规模。
- **Encoder-Decoder**：T5、BART 等把输入编码与条件输出解码分开，适合 Seq2Seq。不能因通用聊天偏向 Decoder，就宣称翻译、检索、分类全部收敛到同一种架构。

这些是网络组织方式；**Dense/MoE、Base/Instruct、是否推理、是否多模态**是另外几个维度。一个模型可以同时是 Decoder-Only、MoE、Instruct，并支持可开关的思考模式。[6][7]

### Meta LLaMA 开源系列

这里更准确的说法是**开放权重系列**，使用范围仍受对应许可证约束。Llama 4 模型卡给出 2025-04-05 发布节点：[9]

- **Scout**：109B 总参数、17B 激活参数，16 个专家；标注 10M 上下文。
- **Maverick**：400B 总参数、17B 激活参数，128 个专家；标注 1M 上下文。

这些是模型卡口径，不是本机吞吐或满窗口验收结果。MoE 类比“按需路由到专家”有帮助，但专家通常是神经网络子模块，不是可随便独立发布的业务微服务。每 Token 激活 17B 不表示只需存储 17B 权重；权重驻留、跨设备通信、缓存与并发仍会决定部署成本。

### 其他重要玩家

- **DeepSeek-V3**：官方报告为 671B 总参数、每 Token 激活 37B，使用 MLA、DeepSeekMoE 和 FP8 混合精度训练。[6] 报告所述成本覆盖正式训练，不含前期研究和消融实验。不能据此改写成“公司总研发成本”，也不能把效率提升全部归因于 FP8。
- **Qwen3**：官方发布日为 **2025-04-29**，不是旧稿的 2025.10。首批既有 Dense 型号，也有 235B-A22B 与 30B-A3B 两个 MoE 型号，发布文明确区分总参数与激活参数，并介绍思考/非思考模式。[7] 同系列仍须按具体 checkpoint 核许可证、模板与上下文配置。
- **Mistral、xAI Grok、Doubao**：保留为进一步研究入口。本轮不沿用旧稿未经来源核实的版本号、发布日期和“市场领先/国内首选”结论；若纳入项目候选，应补官方模型卡和实际端点测试后再比较。

## Scaling Law 与训练范式

### Chinchilla Scaling Law

DeepMind 的研究问的是：**固定训练 FLOPs 预算，参数量与训练 Token 怎么分配，才能降低损失？** 其实验支持两者按相近比例扩大，并报告 70B 参数、1.4T 训练 Token 的 Chinchilla。[10]

“训练 Token 约为参数量的 20 倍”可以帮助记忆该实例的量级，但不是适用于任何模型、任何数据质量的必守比例，更不是最大上下文窗口。训练 Token 是训练期间累计读取的数据；上下文窗口是一次推理可处理的信息容量，两者不能混为一谈。

若目标变为总生命周期成本，还必须计入部署后的调用量、延迟与硬件预算。更小模型经过更多训练，可能有利于大量重复推理；是否值得需用真实工作负载算账，不能只按参数量排序。

### 后 Scaling Law 时代的新趋势

1. **Test-Time Compute**：给推理过程更多计算预算；需要控制延迟和工具循环，并用客观验收衡量增益，不把“输出更长”当“更正确”。
2. **MoE 稀疏激活**：分开看总权重与每 Token 激活计算；小批量与大批量、单机与跨机的瓶颈不同。
3. **蒸馏与量化**：蒸馏改变学习过程，量化改变表示精度；权重量化与 KV-cache 量化也不是一回事。压缩后必须重新测任务准确率。
4. **FP8 混合精度**：DeepSeek-V3 是大规模实证，不是“此前从未有人用 FP8”，也没有证据支持旧稿统一降低 80% 成本的结论。[6]
5. **多 Agent 协作**：是系统编排方式，不是把单个模型权重拆成多个 Agent。通信、重复上下文与失败重试可能增加成本。
6. **模型与执行系统协同**：模型可以提出工具调用，真正执行仍在宿主、沙箱和权限体系中；原生工具能力不自动授予生产环境操作权。

推理内存也不能只算权重。Hugging Face 当前 Cache 文档区分动态、静态、量化与 offloading：静态分配有利于部分编译路径但可能浪费空间；offloading 通过 CPU/GPU 搬运节省 GPU 内存，存在速度代价；滑窗/分块注意力的缓存增长与全注意力不同。[12] 不应用一个全注意力估算式覆盖所有架构。

## 工程选型：先约束，再比较模型

### 三种候选路线

- **托管 API**：适合需要迅速验证强模型能力、且数据出域条件允许的任务。减少自建服务负担，但要核区域、留存、限流和平台授权。
- **本地小型 Dense**：适合受限网络、固定分类/提取、可量化验收的业务。模型与服务更可控，但不能因权重装得下就认定质量/吞吐达标。
- **自托管 MoE**：适合愿意承担权重、调度与运维复杂度，并有明确业务质量收益的场景。只看激活参数容易低估内存和通信；不能无工作负载就承诺更便宜。

推荐顺序：数据与授权边界先筛掉不合格方案；对剩余两三项跑同一批数据，再用成功任务成本、p95 延迟、失败类型和维护负担决策。公开榜单仅用于产生候选，不代替业务验收。

### 实例一：SQL Server 工单分类

**设计实例，未执行模型评测。** 假设系统只需把工单归到有限类别：先比较本地小型分类/生成模型与托管轻量模型。输入剔除客户秘密，固定 JSON 字段和允许的类别；模型结果只生成建议，不直接驱动 SQL 写操作。

验收集应包含类别边界、缺字段、无关文本、提示注入与无法归类情况。分别统计类别正确、字段合规、拒答/转人工与总耗时；不能把“JSON 能解析”作为唯一成功标准。测试中若接入 SQL Server 2016，还要单独验证查询兼容性，不让模型输出新版函数后由生产发现问题。

### 实例二：旧 .NET 服务迁移

**设计实例，未执行仓库迁移。** 此时错误成本高，输入不仅是单文件，还包括项目文件、依赖、测试与目标运行环境。可比较托管推理模型与自托管候选；不宜仅因单 Token 便宜就选分类任务的模型。

每项迁移任务都要从固定 Git 快照开始，在隔离工作区构建、测试与审查。成功标准应包括行为回归、配置迁移、安全检查及必要的端到端验证。模型自报完成、能编译和真实业务可用是不同层级。若高能力模型减少返工，单次调用更贵仍可能降低每项已验收任务的总成本；反过来也必须接受测试不支持这一优势的结果。

### 可运行示例：按完整任务核算成本

下面是 **Python 标准库教学代码**，无 SDK、无网络、无生产写入。输入来自已汇总的任务级账本：同一任务的所有重试、失败工具调用及模型费用先合并，失败任务也必须计入总花费。金额用最小计费整数单位，避免二进制浮点带来的货币误差；所有候选必须覆盖同一组任务 ID。

```python
from fractions import Fraction


def task_metrics(rows):
    if not rows:
        raise ValueError("empty evaluation")
    seen = set()
    total_cost = 0
    passed = 0
    for row in rows:
        task_id = row["task_id"]
        cost = row["cost_units"]
        accepted = row["accepted"]
        if not isinstance(task_id, str) or not task_id:
            raise ValueError("invalid task_id")
        if task_id in seen:
            raise ValueError("aggregate retries before evaluation")
        if type(cost) is not int or cost < 0:
            raise ValueError("cost must be a nonnegative integer")
        if type(accepted) is not bool:
            raise ValueError("accepted must be boolean")
        seen.add(task_id)
        total_cost += cost
        passed += int(accepted)
    return {
        "task_ids": frozenset(seen),
        "acceptance_rate": Fraction(passed, len(seen)),
        "cost_per_accepted": Fraction(total_cost, passed) if passed else None,
    }


def choose_candidate(runs, min_acceptance):
    if not isinstance(min_acceptance, Fraction):
        raise ValueError("threshold must be Fraction")
    if not 0 <= min_acceptance <= 1:
        raise ValueError("threshold outside [0, 1]")
    summaries = {name: task_metrics(rows) for name, rows in runs.items()}
    cohorts = {summary["task_ids"] for summary in summaries.values()}
    if len(cohorts) > 1:
        raise ValueError("different evaluation cohorts")
    eligible = [
        (summary["cost_per_accepted"], name)
        for name, summary in summaries.items()
        if summary["acceptance_rate"] >= min_acceptance
        and summary["cost_per_accepted"] is not None
    ]
    return min(eligible)[1] if eligible else None
```

使用约束：`accepted` 必须由测试或人工验收产生，不能直接抄模型自己的判断；评测样本少时，样本通过率不是对未来成功率的统计保证。函数只在通过外部质量门槛后比较账本费用，不负责判断数据权限、p95 延迟和供应商合规。返回 `None` 就是无合格项，不自动放宽门槛。费用相同时按候选名称排序，避免把任意遍历顺序当性能结论。

2026-10-20 从本页代码块提取实现并运行单元测试：覆盖失败费用、零成功、重复任务、不同测试集、字段类型、阈值边界与无候选。测试数据仅为人工构造的函数测试夹具，不对应任何真实模型的价格/成绩；实测范围仅限这段 Python，不包括模型、GPU、SQL Server 或 .NET 迁移。
