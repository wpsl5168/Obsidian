# 把一台计算机装进大模型权重，能让它算得更准吗？

作者：Divyansh Agrawal｜个人博客，2026-10-22。[1]
原文：Qwenputer: a fully functioning, deterministic RISC-V CPU inside Qwen3.5

大模型做长整数运算容易出错，通常可以调用外部计算工具。作者尝试了另一条路：在 Qwen3.5-4B 的权重之外增加计算层，让一颗 CPU 在模型内部执行运算，再加上可跨会话保存的文件系统；以下都是作者报告的实验结果。[1]

## 1. 先让模型内部能准确存取数字

Qwen3.5 的四分之三注意力层使用 Gated DeltaNet：它用一个持续更新的状态矩阵保存信息，但原版并不保证精确存数。[1]

作者把“遗忘系数”设为 1，避免旧值衰减；把写入强度设为 1，让新值完全覆盖旧值；再用只指向一行的地址编码，精确读写指定位置。[1] 这样改造后，状态矩阵就能充当计算机内存，而且大小不会像普通注意力缓存那样随对话增长；将这类机制作为记忆并非新发现，这次实验推进到可精确寻址、运行 CPU 的程度。[1]

## 2. CPU 是编译进去的，不是训练出来的

编译器把“读寄存器、相加、条件跳转”等电路步骤直接写成权重，在 Qwen 原有 32 层前增加 11 层，实现一颗 32 位 RISC-V CPU，原模型权重保持不变。[1] 每条指令通过几个生成的 token 执行，分别携带内存地址、数值和步骤结束标志。[1]

模型沿用熟悉的工具调用格式发出计算请求，但执行发生在内部计算层，不调用外部计算服务，也没有为此追加训练。[1] 不过，它仍需要 RvChat 驱动加载固件，并阻止执行轨迹进入原来的语言模型层；“内部计算”不等于无需配套程序。[1]

## 3. 算术明显改善，但不全面超过外接 Python

作者报告，CPU 通过官方 riscv-tests，程序结果与模拟器 qemu 一致；连续运行 1800 万条指令没有错误，期间没有参考机器逐步纠正。[1] 另一项检查将约 23 万个输出位置与参考机器对照，也没有发现差异。[1]

在 NUPA 长整数算术集上，原版 Qwen 的正确率为 48.6%，Qwenputer 达到 100%，与接入 Python 工具相同。[1] 在 DeepMind 测试集中，按“Qwenputer／外接 Python／原版”排列：大整数除法为 97.5%／95%／72.5%，乘法为 97.5%／100%／55%，较长混合乘除为 100%／97.5%／90%，大整数加减为 97.5%／97.5%／87.5%。[1]

因此，内部 CPU 的可靠执行不代表每道题都能答对，也没有在这些测试中全面胜过外部工具。[1] 作者另测得普通文本输出分布差异接近噪声水平，但这不是所有语言能力均不受影响的全面评测。[1]

## 4. 同一块内部内存，还能保存“文件”

实验分支增加了写入、追加、读取、列举和删除操作：文件名用于定位目录，正文存入其他状态矩阵，查找通常只需两三步，不必扫描全部内容。[1] 它最多保存 512 个文件、约 5.3 万 token 文本；要跨会话保留，必须在结束时保存状态，下次再加载，不是凭空获得永久记忆。[1]

## 5. 记住变化的事实，比重贴旧聊天更有效

作者报告，针对跨会话发生变化的事实，文件系统方案答对 90%，直接把旧聊天贴回去为 30%。[1] 文章另列出与 Python 记忆工具的比较：83.3% 对 78.9%，作者称两者表现相当。[1] 这两组数字不能拼成同一场排名：正文没有完整交代题集、样本量和两组测试的条件对应关系，文件系统也仍属实验版本。[1]

## 6. 代价是更大、更慢，调用流程也没做完

新增层和更宽的内部表示使模型文件达到 18.8 GB，约为原版两倍，虽然其中大部分是零填充；作者给出的运行配置是一张 24 GB 显存的 GPU。[1] 它不能直接用普通的 generate() 调用，每条 CPU 指令又要消耗几个解码 token，所以较大计算耗时是秒级，而非毫秒级。[1] 基准测试使用的批量执行器在 L4 GPU 上约跑 3200 个 CPU token／秒，这不是每秒指令数，也不是正常聊天输出速度。[1]

内部 CPU 已能运行 C 和 MicroPython，但还不是能承载 Linux 的完整计算机。[1] 下一步是让 Qwen 自动写 Python 并通过内部接口执行，以及提高速度；代码和模型已公开，作者还把它用于后续的隐藏推理与内置监督研究，本文没有展开那些研究的验证。[1]
