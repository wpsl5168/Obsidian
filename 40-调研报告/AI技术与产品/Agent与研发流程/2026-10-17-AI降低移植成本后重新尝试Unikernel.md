# AI 降低了移植成本，Unikernel 值得重新尝试吗？

Geoffrey Huntley｜个人博客｜2026-10-10
原题：unikernels were hard. key word: were.[1]

Unikernel 把应用和它需要的系统功能合成一个专用系统，不再在下面放一套完整的通用操作环境。Huntley 与曾参与 MirageOS 的 Justin Cormack 讨论：过去缺库、缺驱动而难以落地的方案，能否借助编程 Agent 重新尝试？下文是作者整理的对谈要点。[1]

## 1. 过去难在配套不足，现在尝试让 AI 补齐

Unikernel 不能随手启动系统里的另一个程序；要提供网页、解析域名或发邮件，就需要相应的库。Justin 回忆，早期 Mirage 已有网络协议支持，存储能力却严重不足，还要从 NetBSD 搬驱动。[1]

Huntley 主张，模型已经学过这些技术，补库与移植的成本发生了变化，不能继续把“以前很难”当成今天不尝试的理由。这是他的经验判断。[1]

## 2. 去掉通用工具，能否让攻击更难继续？

作者把为人类操作员准备的通用系统视为应用的额外负担：应用失守后，攻击者往往利用 shell——执行系统命令的环境——继续窃取数据。他认为，去掉 shell 和解释器，可使套用通用漏洞的攻击转向针对具体应用的攻击。[1]

但 Justin 提醒，删除 shell 并不等于消除执行能力，内存安全漏洞及可被拼接利用的代码片段仍须考虑。文中也承认，早期一些 Unikernel 让应用与系统处于同一权限级别。[1]

Huntley 主张航天等场景考虑经过形式化验证的 seL4，其他安全敏感应用认真考虑 Unikernel，并认为 AI 能帮助补上权限隔离。这些是他的选型立场，不是文中已经证明的安全保证。[1]

## 3. 移植能否可靠，取决于有没有可运行的对照

Justin 举的例子来自极简 Linux 设备镜像，并非一个已部署的 Unikernel：为了避免带入整套文件系统工具依赖，他与 Agent 用 Rust 在几小时重写了创建 XFS 文件系统的 `mkfs.xfs`。[1]

据其描述，新实现解释全部参数，并跨不同块大小测试，输出与原工具逐字节相同。做法是让两个实现生成不同大小的文件系统，再比较结果、移植测试；原工具提供了明确的检验依据。[1]

存储方面，两人赞成用对象存储 S3 保存主体数据、用本地 NVMe 固态盘缓存常用数据，以支持扩展和多用户访问，前提是延迟不是主要约束。[1]

## 4. 不只写应用，还要测试机器之间如何配合

作者推崇 NixOS 机器测试：一次启动多台测试机器，检查应用与网络规则的实际互动。遇到上游缺陷或依赖供应链问题，他主张通过 overlay——在自己的构建中替换或修补依赖——让 Agent 能直接改源码，而非只能等待维护者修复。[1]

他还展示了 Spaceleans：把微软 Orleans 分布式框架移植到 OCaml，作为 Unikernel 运行。它把业务对象分布到多台机器，交由运行时负责定位，并在需要时从存储恢复，开发者不必逐一指定对象在哪台机器上。[1]

配套包括多时间源校时、网络与支付客户端、HTTP 重试，以及在日志入口保护个人信息和秘密的包装层。作者称包含文件系统的整体工作用了一周，但也说可能永不发布；这是个人原型自述。[1]

## 5. AI 写得快，编译与纠错仍然会卡住流程

Huntley 喜欢 OCaml 的接口文件和快编译：接口文件能简洁说明模块应当怎样工作，编译器则及时阻止错误。Justin 的约百万行 Rust 项目中，四个 Agent 同时编译会争抢 CPU 和磁盘；等待越久，每分钟能尝试的修复越少，快机器的支出甚至超过 token。[1]

两人也讨论了运行时限制：Huntley 担心 Haskell 的内存滞留问题到生产环境才暴露；他发现让 Agent 在 Rust 中采用预先分配、此后不再增长内存的策略很难，并将其归因于训练示例不足。他看好能把更多约束写进类型系统、交给编译器检查的依赖类型；这是其语言判断与预测。[1]

## 6. 模型可以使用没学过的语言，但过程并不轻松

作者以自己创建的 Cursed 语言为例：使用 Sonnet 3.5、3.7 和刻意不充分的提示，连续循环开发三个月；实现语言先选 C，再换 Rust，最后换 Zig。他认为 C 提供的错误约束不足，改用 Zig 也是失误。[1]

他提到约 6,000 美元，并说做了三遍，但没有说清这笔费用是否覆盖三轮。[1]

其经验是，把词法与语法规则放进上下文，模型就能使用训练中没有见过的新语言，不一定需要微调，但这种办法粗放而低效。他设想继续补齐能编译自身的编译器、标准库和语言服务，也主张语言升级附带迁移技能，让 Agent 处理不兼容变更。[1]

## 7. 文章落脚在重新试验，不是所有原型都要发布

Huntley 希望开发者重访过去嫌贵、嫌难的研究方案，并要求管理者留出 AI 试验时间；他还预测，六个月内管理层会提出人员绩效分层要求。这个时间判断属于作者预测。[1]

他明确说，许多项目是练习，模型进步后会重做，一些可能永远不发布。[1]
