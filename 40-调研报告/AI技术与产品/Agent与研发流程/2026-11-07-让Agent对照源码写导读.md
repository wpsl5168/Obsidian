# AI 把程序写好了，怎样补上自己没看懂的部分？

原文：Linear walkthroughs
作者：Simon Willison｜《Agentic Engineering Patterns》系列；页面未注明发布日期。

让 AI 写出一个能用的程序后，作者发现自己并不知道它内部怎样运转。[1]
这篇文章讲的是：再让编程 Agent 对照真实源码写一份有顺序的导读，把生成的软件变成可以学习的材料。[1]

## 1. 程序已经发布，作者才发现自己不了解实现

Simon 在 Mac 上用 Claude Code 和 Opus 4.6 做了一个幻灯片应用，使用苹果的界面开发框架 SwiftUI。[1]
他打算在演讲结尾揭晓：连放幻灯片的软件也是 AI 写的。[1]
但代码发布到 GitHub 后，他意识到，自己一路靠提示让程序成形，几乎没有注意生成的代码。[1]
文章也把这种导读用于另外两种情况：接手陌生代码，或者重新理解自己已经忘记细节的旧代码；前提是模型能力与配套的 Agent 运行工具合适。[1]

## 2. 先读源码、安排讲解顺序，再写导读

他新开了一个网页端 Claude Code 会话，让它访问代码仓库，明确要求“阅读源码，然后规划一份按顺序解释代码如何工作的详细导读”。[1]
接着让 Agent 先查看 Showboat 的命令行帮助，学会使用这个文档工具，再在仓库里创建 walkthrough.md，把讲解写进去。[1]
这里有人的明确安排：既指定先读再规划，也指定文档位置和引用代码的方法，并非只问一句“解释一下这个项目”。[1]

## 3. 解释可以由模型写，代码片段从文件里直接取

Showboat 是作者开发的工具，用来让 Agent 制作展示工作过程的文档。[1]
其中，`showboat note` 添加文字说明；`showboat exec` 执行一条 shell 命令，并把命令及其实际输出一起写入文档。[1]
作者要求 Agent 用命令提取正在讲解的源码片段，避免让模型手动复制代码时引入幻觉或抄写错误；这个安排解决的是代码片段的取材方式。[1]

## 4. 得到的是覆盖实际项目的导读

生成的文档逐一详细讲解了项目全部六个 `.swift` 文件。[1]
Simon 说，阅读它让自己理解了 SwiftUI 应用的结构，也学到了一些 Swift 语言细节；这是他对这个项目的个人使用反馈。[1]

## 5. 小项目做完后，还能接着用来学习

对于担心大模型会拖慢自己学习新技能的人，作者推荐采用这种做法：让 Agent 帮忙建立理解，而不只负责交付程序。[1]
他举的尺度是一个约40分钟做出的玩具项目，也能成为探索新技术生态的材料；这个时间描述的是项目，不是生成导读或学会 Swift 所需的时间。[1]
