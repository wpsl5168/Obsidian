# 如何用大模型辅助写作，又保留自己的表达

原文：How To Write With An LLM
来源：Sockpuppet｜2026-09-17。[1]

这篇文章讨论如何让 LLM 减轻修改文章的负担，又不让模型接管措辞和判断。[1]作者提出的流程是：先自己写完，再让模型找毛病，把它用作文字编辑，而非代笔。[1]

**1. 不直接采用模型提供的具体措辞。**

作者给自己设了一条严格规则：即使模型建议的句子听起来更好，也不直接拿来用。[1]他认为，模型擅长挑选讨喜的表达，但这些表述常像杂志标题；单独看很漂亮，整篇堆起来却不自然。[1]这条规则的用意，是避免依赖自己未必可靠的辨别力，逐句判断哪些“AI 味”可以接受。[1]

**2. 赞美也可能干扰修改。**

文章指出，模型对结构、过渡、比喻的肯定，可能让作者加倍坚持初稿里的选择，放弃原本会做的重写和调整；而这些重新思考的过程，也是个人文风的一部分。[1]作者曾假称自己是筛选来稿的编辑，以减少迎合，但模型又容易过度贴合虚构刊物的目标。[1]他目前的办法是明确禁止鼓励，并留意回复中的赞美。[1]

**3. 把繁琐的文字检查交给模型。**

文中列出的用途很具体：检查被动语态是否过多、动词是否被改成拖沓的名词结构、措辞是否重复，以及是否到处都是 very、really、actually 之类的修饰词。[1]模型还可以指出哪些段落换个位置会更清楚。[1]作者推荐从《Style: Lessons In Clarity And Grace》一类写作指南中整理检查项，再让模型分轮处理，而非笼统要求“润色全文”。[1]

**4. 自己改写，再让不了解修改过程的模型比较。**

具体循环是：模型指出问题，作者重写相应句子或段落，再把新旧版本交给模型比较。[1]但如果沿用原来的对话，模型知道作者刚做了修改，也知道作者希望新稿更好，评价就可能继续迎合。[1]因此，文章建议把两个版本交给没有这段修改上下文的模型。[1]

**5. 用工具管理多轮检查和版本。**

作者不想继续在多个标签页之间来回切换，于是搭了一个写作工作台。[1]他给出的初始需求包括 Python、HTMX、SQLite 和 Tailwind，以及文本高亮、对应的侧边批注、逐条浏览建议、多文档和修订记录。[1]再把事先整理的检查提示，通过 Codex、Claude 或 Antigravity CLI 分别运行；工具负责组织检查，具体改写仍由作者完成。[1]

**6. 保留不接受建议的权利。**

结尾用这篇文章本身举例：GPT5 认为全文长了约 20%，作者承认它可能说得对，但仍决定不删。[1]文章最后保留的界限是：可以把重复、费神的检查交出去，但不必接受每一条修改建议。[1]
