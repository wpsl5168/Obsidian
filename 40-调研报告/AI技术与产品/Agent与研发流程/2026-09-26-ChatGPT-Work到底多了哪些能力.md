# ChatGPT Work 到底多了哪些能力？

Simon Willison｜Understanding ChatGPT Work｜2026-08-30。[1]

作者通过实际试用，整理 Work 与普通 Chat 的功能差别，以及产品说明没有讲清的地方。以下是他写作时的观察，不代表今天所有账户的功能状态。[1]

## 1. 先分清云端与本地版本

作者把运行在云端的版本称为 Work Cloud，把能在自己电脑上访问文件、运行程序的版本称为 Work Local；后文只讨论 Cloud，桌面客户端也能选择云端运行。[1]

当时 Work 面向每月20美元及以上订阅者，可选 GPT-5.6 Sol、Luna、Terra 及不同推理强度，也可选 GPT-5.5。[1] 他推测 Work 使用 Codex 的额度，普通 Chat 使用另一套额度，但没有把这点写成已确认的计费规则。[1]

## 2. 代码能联网，浏览器能实际操作网页

他最看重的是代码执行环境可以访问互联网：克隆 GitHub 仓库、安装依赖，再调用网站或 API；网络可设允许域名列表，而默认似乎更开放。[1]

另一个差别是完整的无界面 Chrome，可以填表、截图、执行 JavaScript 提取页面内容；他用它读取自己博客的标题，并指出手机上也能发起这样的任务。[1] 需要登录时，用户可接管浏览器输入密码和双重验证代码，而不让这些凭据经过模型。[1]

## 3. 文件能跨会话保留，但运行环境并非完全共享

普通 Chat 的各会话文件系统相互独立；Work 为每次会话建立 scratch 目录，却能跨会话访问此前的文件。[1] 按作者观察，多个运行中的会话能立即看到彼此对共享目录的修改，但似乎不共享进程空间，一个会话启动的 localhost 服务也不能被另一个访问。[1]

## 4. 可以把调查结果做成网站，再定时更新

Work 能用 Cloudflare Workers 构建并部署网站，也能结合 D1、R2 实现带状态的服务端功能。[1] 作者的例子是调查伦敦哪些地方有“鹈鹕哺雏”的宗教图像，整理成 JSON，再生成展示网站；网站默认私有，可改为公开，团队方案还能分享给指定成员。[1]

定时任务可以每天搜索 Waymo 是否宣布在指定地区上线，也可与建站结合，按小时更新网站。[1] 但他在更新中纠正：普通 Chat 似乎也支持定时任务，不能将它算作 Work 独有能力。[1]

## 5. 复杂项目可以调用并行子 Agent

文章介绍 Work 能运行使用 Sol、Luna、Terra 的子 Agent，而普通 Chat 不具备这项能力。[1] 作者把它定位为高级功能，适用于能从多个 Agent 并行协作中受益的复杂项目，没有声称所有任务都会因此改善。[1]

## 6. 安全性仍是作者没有得到明确答案的问题

他关注三项能力同时出现的风险：访问私有数据、接触不可信内容，以及向外部发送信息。[1] Work 在他的观察中同时具备这三项，因此他希望 OpenAI 解释如何防御 prompt injection；他猜测可能沿用 Codex 的自动审查机制，但原文没有确认。[1]

## 7. 只看工具列表，还看不全系统能力

作者认为，官方更常解释 Work “适合做什么”，却没有清楚公开“具体能做什么”，系统提示词和工具说明也不够透明。[1]

他让 Work 生成工具文档网站，列出223个工具，其中6个来自他自己的 MCP，并非产品内置；随后又发现44个 Skills，涵盖文档、表格、PDF、建站等操作。[1] 起初列表里只有 web.run，看不出完整浏览器自动化能力，继续读取 control-browser Skill 后，才看到通过 Node REPL 调用浏览器运行时的路径。[1]
