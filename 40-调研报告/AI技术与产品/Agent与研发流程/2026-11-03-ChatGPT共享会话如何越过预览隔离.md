# 点开共享会话，为什么能读到别人的私密聊天？

原文：Do the Math: How We Took Over ChatGPT Accounts
作者：Mukul Goyal / Parameter Labs，2026年10月28日。[1]

Parameter 团队发现，ChatGPT 的网页预览虽然被隔离，仍可通过同页的图表组件，把恶意代码送进已登录用户的主页面，进而读取私密会话；文章称 OpenAI 已于10月26日修复。[1]

## 1. “只点一个链接”有具体复现条件

攻击入口是正常的 ChatGPT 公开分享链接，访问者需要处于登录状态，不必安装应用、加入攻击者工作区或粘贴代码。[1]

但研究中有两个版本：最稳定的版本需要打开链接后，再点一次预览按钮（Preview）；后来让预览自动打开，才做到只点击分享链接。[1] 自动版本在另一个账号上复现了3次，包括强制刷新后，约4.5秒出现验证弹窗；这不是大规模成功率测试。[1]

## 2. 预览不能读主页面，却能给主页面发消息

ChatGPT 把生成的网页放进另一网址下的受限内嵌窗口，里面的代码确实无法直接读取外面的主页面。[1] 但同一会话里的交互图表加载了 MathLive 数学组件，它在主页面接收虚拟键盘设置消息。[1]

浏览器允许隔离窗口通过 postMessage 交换消息；问题是这个接收器没有验证发送方的网址，也不要求消息来自事先获准的窗口。[1] 攻击代码因此能要求它修改键盘布局，再显示键盘，而布局竟允许夹带任意 HTML 网页内容。[1]

## 3. 从插入网页内容，到获得主站执行权限

MathLive 把这些内容直接插入主页面；看似负责处理安全的 createHTML，只把字符串标记为可信，并没有清除危险内容。[1]

直接塞入脚本还不会运行，研究者于是插入一个新的内嵌窗口：它没有隔离限制，又继承了 ChatGPT 主站身份，因此可以访问主页面。[1] 但它仍受 CSP 约束——这是浏览器限制网页从哪里加载脚本的规则，当时禁止直接写入脚本，却允许加载 YouTube 的脚本。[1]

研究者找到的 YouTube 接口，本来允许调用方指定接收结果的函数，却把传入的恶意代码也写进了可执行响应，连校验报错时都如此，于是这道限制也被绕过。[1] 原来的预览始终处于隔离中，越界发生在主页面组件替它创建的新窗口里。[1]

## 4. 做成可分享链接，还要解决组件缺失和加载先后

最初版本需要受害者连接研究者的 ChatGPT App；改用 HTML 附件后，公开分享又丢掉了前面的图表，导致没人接收恶意消息。[1] 最后，团队把真实图表和助手生成的 HTML 预览直接放进同一个公开会话，才保住完整链路。[1]

两者独立加载，预览可能抢在图表组件就绪前发消息，因此最终版本会在有限时间内重试，并保证私聊读取和外传只执行一次。[1]

## 5. 实验证明读到了私聊，不只是弹了个窗口

代码利用页面已有的登录信息调用 ChatGPT 接口，列出近期会话，再读取一段从未分享给攻击者、也与恶意链接无关的私密聊天。[1] 随后通过一次图片请求，把响应中少量选定数据送到研究者服务器；这不是仅抓取屏幕上可见的文字，也不等于实验中已外传全部聊天记录。[1]

作者据此认为，同一权限下其他前端接口提供的数据与账号操作也可能受影响；文中具体展示的验证是会话枚举、私聊读取和少量数据外传，没有逐项验证所有账号操作。[1]

## 6. 修复针对跨窗口信任，而不只是封一个网址

据文中时间线，团队10月18日报告漏洞，OpenAI 于21日复现并把等级从 P2 升至 P1，26日确认解决，奖金共5,000美元。[1] 修复覆盖两个网页前端版本；中途调整 CSP 只阻断了部分攻击链，最终两个版本都拒绝了报告中的跨窗口消息。[1]

文章强调，单封 YouTube 接口仍会留下恶意 HTML 进入主页面的问题。[1] 作者给出的防护要点是：同时核验发送网址和具体窗口，不让跨窗口设置携带原始 HTML，让不可信内容生成的新页面继续保持隔离，把 CSP 当作补充防线，并测试分享、图表与预览组合后的行为。[1]
