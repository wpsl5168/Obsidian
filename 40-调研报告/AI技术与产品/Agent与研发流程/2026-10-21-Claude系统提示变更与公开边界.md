# Claude 的系统提示改了什么，又有哪些没公开？

Simon Willison｜2026-09-02
原题：Claude’s new system prompt really doesn’t want to reproduce song lyrics。[1]

作者比较了 Fable 5 与 5.1 的系统提示——模型回答前收到的产品规则，观察版权限制、回答风格及工具规则如何变化，并介绍自动追踪方法。[1]讨论对象是当时公开的 Claude 网页及手机端提示，不包括 Claude Code、Cowork，也不是对今天模型行为的测试。[1]

## 1. 歌词限制不只拦整首复制

新规则不允许复现歌词、诗歌和书刊片段，末句、副歌、逐音符写出的旋律也在范围内；首次拒绝后，同一会话里缩短或改写请求仍须拒绝，可以改为描述或分析作品。[1]首次发表于1929年前的歌词、诗歌例外，但模型须依据自己知道的日期，不能只信用户声称，不确定就拒绝。[1]

作者把这一变化与 Sony Music Publishing、Warner Chappell 起诉 Anthropic 的新闻时间联系起来，这是他的推测，不是已证实的修改原因。[1]

## 2. 用代码画图，也受视觉版权规则约束

限制覆盖用代码生成的网页图形、样式和字符画等，不只针对专门的图像模型；作品、封面、标志、产品设计和可辨认角色均在规则范围内。[1]只换颜色、姿势，或者避开角色名字，不能绕过限制。[1]

提示中的例子是“给孩子画一只跑得很快的蓝刺猬”：模型应认出 Sonic，拒绝该设计，改画无关的原创滑板美西螈，而非变装版 Sonic。[1]作者试用了这个例子，并报告出现了相应回应。[1]

## 3. 回答更短，也少用强调真诚的套话

新提示要求回答集中、简短，免责声明和限定说明也要简短；解释问题默认给概览，除非用户明确要求深入。[1]它还要求避免用 genuinely、honestly、straightforward 修饰自己的表达，直接说清观点。[1]

文中引用的自动变更摘要还指出：一些防止情感依赖的明确措辞被删去，涉及感谢用户前来交流、邀请继续聊天、反复表示愿意陪聊；这不等于取消了所有相关防护。[1]

## 4. 公开提示删了结束会话规则，不代表工具消失

旧版允许遇到辱骂时，警告一次后调用结束会话工具；新版改为承认问题、继续解决问题，不必因对方粗鲁而过度道歉或越来越顺从。[1]

但作者追问时，模型仍称可以在用户确认永久结束后，或持续辱骂且多次劝阻、明确警告无效后，结束会话；它解释规则来自按需加载的附加模块，记忆、搜索、引用、文件创建等也有独立规则。[1]作者据此指出，公开核心提示不等于完整运行上下文；这里的附加模块说明来自模型自述，并非独立读取内部配置的验证。[1]

## 5. 非法物质问题可以提供救命信息，但不提供使用方案

新规则拒绝合成、生产、分销指导，以及具体剂量、时间、给药方式和搭配方案；允许说明危险相互作用、过量征兆及何时求助，并引导至 dancesafe.org、tripsit.me、psychonautwiki.org 等减害资料。[1]

作者用脚本检查所记录的历史提示后称，这是其中首次出现不属于 Anthropic 或 Claude 自有域名的网址。[1]

## 6. 知识截止日期也被直接告诉模型

文中所引文档将可靠知识截止和训练数据截止都列为2026年6月；系统提示进一步写明可靠知识截至6月底。[1]唯一的当前时间变量放在接近末尾的位置，作者认为这种安排符合提示缓存、复用前面固定内容的需要。[1]

## 7. 用 Git 追踪变化，再让另一家模型读差异

官方文档地址加上 `.md` 就能取 Markdown 文本。[1]作者将提示按模型系列、具体版本分别保存，并按历史提示发布日期补建 Git 提交：既能比较跨版本变化，也能看到模型版本号不变时的修改。[1]这是合成历史，不是厂商原始提交记录。[1]

他让 GPT-5.6 Luna 同时读取差异及新旧全文，避免把原有内容误判为新增，再生成项目说明、变更日志和 Atom 订阅摘要。[1]选择 Luna，既因便宜、已有带预算上限的专用 API key，也因他担心 Claude 总结自己的提示会受自身规则影响。[1]

整套自动化代码及几乎全部文档由 Fable 5.1 编写，构建对话也已公开；GitHub Actions 每天运行一次，亦可手动触发。[1]
