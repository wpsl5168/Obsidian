# 让 Agent 把新功能操作一遍，录成演示视频

Simon Willison｜2026年6月30日。[1]
原文：Have your agent record video demos of its work with shot-scraper video。[1]

Simon 想让编程 Agent 不仅提交代码，还能把做出的功能演示出来；他在这篇文章中介绍了网页演示录制工具，以及自己怎样与 Agent 一起完成它。[1]

## 1. 给出操作步骤，让浏览器边操作边录制

shot-scraper 1.10 新增了 video 命令：读取 `storyboard.yml`，也就是一份按顺序写明操作的脚本，再用浏览器自动化工具 Playwright 操作网页并录像。[1]

脚本可以安排点击、填表、等待指定文字出现，以及停顿多久；示例还指定了启动哪个本地服务、打开哪个页面、使用多大的浏览器窗口，并通过命令输出 MP4。[1]

## 2. 示例完整走过“粘贴数据、预览、保存”

文章演示的是 Datasette 当时仍在开发的数据导入功能：它支持从粘贴的 CSV、TSV 或 JSON 创建表，而展示的脚本使用 CSV。[1]

脚本先向已有表插入三行数据，等待预览和插入成功提示，再检查页面中出现了新记录；随后创建 `launch_metrics` 表，同样先预览三行数据，再保存并等待新表页面出现。[1]

这是一个有准备的演示环境：作者使用演示数据库和含登录 cookie 的认证文件，脚本还用 JavaScript 模拟了剪贴板读写，不能把它理解为对真实系统剪贴板的测试。[1]

## 3. Agent 先读帮助，再按人的要求录制

演示脚本由 Codex Desktop 中的 GPT-5.5 xhigh 编写，但任务和环境由人指定：审阅当前分支的改动，读取 `shot-scraper video --help`，创建演示数据库，启动指定开发服务器，然后录下新功能。[1]

Simon 喜欢把足够详细的使用说明直接放进命令行帮助，让 Agent 现场学会工具；他把这种方式比作将 `SKILL.md` 内置于工具，而不是另外提供一份技能文件。[1]

## 4. 能录到画面，还不等于适合做产品演示

他几年前就试过这条路线：早期 Playwright 录像会带上有助调试、却不适合演示的界面元素；后来这个问题修好了，录像又会因为在网页加载前启动而出现开头白帧。[1]

Playwright 1.59 增加了更精细的录屏控制，但输出宽度仍固定为800像素。[1]修复代码虽然已经合并，却尚未发布；直到文章发表前一天，playwright-python 1.61.0 发布，最后这项阻碍才解除。[1]

## 5. AI 写代码，人通过文档检查设计

功能代码也全部由同一模型编写。[1]Simon 还让它写文档，再从文档中寻找冗余、不一致和难理解的设计，要求修改；不少迭代正是这样发生的。[1]

YAML 脚本格式主要由 Agent 设计，但作者指定使用 Pydantic——在这里负责定义允许的字段并检查输入格式的库——让设计更容易审查。[1]

## 6. 这是一个长期没时间做的功能

原始需求在2024年2月就已提出，Simon 一直难以从其他项目中抽出时间。[1]他说，没有编程 Agent 支持，自己几乎肯定不会承接这项功能。[1]
