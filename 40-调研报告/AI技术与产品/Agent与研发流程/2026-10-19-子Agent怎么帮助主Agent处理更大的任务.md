# 子 Agent 怎么帮助主 Agent 处理更大的任务？

原文：《Subagents》
作者：Simon Willison｜《Agentic Engineering Patterns》章节，页面未注明发布日期。[1]

编程 Agent 处理项目时，往往要查代码、读日志、跑测试。[1]这些过程会占用它当前能容纳的信息空间；本文解释怎样把部分工作交给子 Agent，让主 Agent 留出空间继续处理任务。[1]

## 1. 模型能力增强了，能同时容纳的信息仍有限

“上下文”就是模型当前工作时能看到的信息，包括提示词、代码和工具输出。作者指出，在他讨论的时期，模型能力显著提升，但过去两年的上下文上限增长不大：通常最高约100万 token，评测常在低于20万 token 时得到更好结果。[1]

Token 是模型计量文本的单位，不等于字数；这里的数字是作者对当时情况的概括，不是所有模型通用的硬门槛。[1]

## 2. 把探索过程放进另一个窗口，主 Agent 接收结果

子 Agent 可以理解为主 Agent 派出的一个新实例：带着明确目标和新的提示词，在独立上下文中工作，再返回发现。[1]

它的价值在于，搜索、阅读等过程不必全部占用主 Agent 的窗口。[1]作者举出的基础方式是主 Agent 发出任务后暂停等待，类似调用普通工具；使用子 Agent 并不必然意味着并行加速。[1]

## 3. 一个实际案例：先找齐修改页面需要的代码

作者想给博客的版本差异页面加功能：除了用红绿背景标出变化的行，还要用更深颜色突出行内具体改动的字符。[1]他把截图和要求交给 Claude Code。[1]

Claude Code 先派 Explore 子 Agent 查四类内容：页面模板、生成差异的 Python 代码、相关 JavaScript 和 CSS 样式，并明确搜索目录与关键词。[1]

子 Agent 返回了文件位置、函数和实现说明，例如定位到生成差异的 `chapter_changes()` 函数。[1]主 Agent 拿到这些信息后便能开始修改；这里展示的是“探索并交回所需信息”，不是子 Agent 独立完成全部开发。[1]

## 4. 多项工作互不依赖时，可以并行提速

主 Agent 也可以同时派出多个子 Agent，必要时使用 Haiku 这类更快、更便宜的模型。[1]作者给出的指令例子是：“用子 Agent 找出并更新所有受这次变更影响的模板。”[1]

他特别限定：涉及多个文件、这些文件彼此不依赖时，这样做可能显著提速。[1]

## 5. 专门角色的作用，是承担具体工作和大量中间输出

部分编程工具允许用专用系统提示词或工具配置子 Agent。[1]文中列出三种用途：

- 代码审查：找 bug、功能缺口和设计薄弱处。[1]
- 跑测试：尤其适合输出冗长的测试套件；子 Agent 处理完整日志，只向主 Agent 返回失败细节。[1]
- 调试：用自己的上下文预算分析代码、运行片段，寻找复现步骤和故障原因。[1]

## 6. 不必为了分工而拆出几十种角色

作者最后提醒，子 Agent 的主要价值是保护主 Agent 的上下文，处理消耗大量 token 的操作。[1]只要还有足够的上下文预算，主 Agent 本身也可以调试和审查自己的代码；不必把每种工作都另设一个角色。[1]
