# 让 AI 把游戏做得更好玩：Battle Drones 的迭代过程

Simon Willison｜个人博客｜2026-10-20，含原文后续更新。[1]

Simon 想做一款手机上能玩的《命令与征服》式即时战略游戏：采资源、建基地、指挥部队交战。[1]他记录了 Battle Drones 从“能运行但无聊”，经过多轮试玩和修改，变成自己愿意玩的游戏的过程。[1]

## 1. 画面变好，没有立刻让游戏好玩

他从7月的 Claude Fable 5 开始，10月换用 Opus 5.5；还提供 OpenAI API 密钥，让 Agent 生成游戏图片。[1]初版能建造和指挥单位，后来补齐车辆图片、增加地图，作者仍很快玩腻。[1]

写作时项目已历经12次主要迭代、321次 Agent 提交。[1]他几乎没审查代码，也不熟悉使用的 TypeScript，但进行了大量试玩；这不是无人参与的一次生成。[1]

## 2. “更好玩”的背后，是通宵修改和模拟对战

他输入“Make it a LOT more fun”，使用的是 Ultracode 模式——通过脚本同时组织多个子 Agent 工作，从晚上一直跑到次日上午较晚才得到可玩版本。[1]

改动包括开局路线选择、争夺地图中央目标、落后方翻盘机会、范围攻击技能，以及生存模式和战役。[1]Claude 跑了上千场模拟对战，据此调整单位和规则。[1]

作者引用的、由 Claude 撰写的更新说明称：在普通难度的1,200场内置 AI 对战测试中，25分钟仍未分胜负的比例从14%降至0.9%；胜方曾落后至少800单位废料资源的胜局占比，从24%升至46%。[1]这些是模拟对战指标，不是人类玩家满意度测试，也不是“落后方的胜率”。[1]

## 3. 作者开始设计“为什么要用这个单位”

随后又用一夜迁到 Three.js，改成由代码构建的3D场景和模型；配乐同样由代码生成，随战况变激烈。[1]

但新增步兵和运输机后，作者发现内置 AI 很少使用它们，因为缺少战略用途。[1]他提出群岛地图：七个岛上据点只能由运输机送去的步兵占领，飞机不能直接占领；并要求先研究、讨论设计，再动手实现。[1]

巨型机甲也是共同讨论的结果：停驻后可以充当新基地，两架运输机可以把它吊走；胜利条件相应改为摧毁敌方总部及全部巨型机甲。[1]

## 4. 大模型也能参战，但不能偷看全图

另外的 Agent 对战模式，让大模型通过工具读取局势、指挥单位，而非必须看画面；信息仍受“战争迷雾”限制，只能获得本方可见内容。[1]文章提供了对局回放，以及检查模型提示和回答的调试工具；这与前述内置 AI 模拟测试不是同一回事。[1]

随机地图则来自一次配额将重置前的尝试：他要求45分钟内开发，地图旋转对称，并用固定种子复现同一布局；45分钟是提出的限时，不是文中核实的完成耗时。[1]

## 5. 为了不养服务器，先让设备用声音联机

作者希望保留静态网页、不长期运维服务器，于是让 Claude 参考自己已有的声音版乒乓球实验，先造工具测设备间传输带宽，再实现声音传数据。[1]

设备必须处于麦克风可听范围。[1]他在笔记本、iPhone、iPad 间试过，但首次介绍时明确说刚做出来，还没充分测试。[1]

## 6. 回放和联机，要求不同浏览器算出相同结果

Chrome 与 Safari 的三角函数曾返回略有差别的数值，导致回放不同步。[1]Claude 因而替换这些函数，让同样输入得到一致的游戏状态。[1]

网页还支持缓存后离线运行，作者曾在飞机上直接玩；开发中也陆续生成了模型浏览器、联机测试和对局调试工具。[1]

## 7. 后续更新：声音引发头痛，还是加了服务器

原文后来补充：Natalie 试玩时被高频联机声弄得严重头痛。[1]作者添加警告，并急着提供替代方式；尝试 WebRTC 后，连自己同一 Wi-Fi 下的两台设备都未连通，于是改用不保存游戏状态的 WebSocket 中转服务器。[1]

它部署在 Fly.io 单台 shared-cpu-1x 实例上，闲置时可缩到零。[1]作者估计，即使整月持续运行，也不超过2.19美元；这是他的成本估算，不是实付账单。[1]玩家可分享房间链接或扫码联网对战，结束后导出 JSON 再回放。[1]

这仍是不熟悉游戏开发的作者做的个人实验。[1]他认为它还不够资格作为正式独立游戏参展，也强调 Ultracode 大量消耗 token；“变好玩了”是他的试玩体验。[1]
