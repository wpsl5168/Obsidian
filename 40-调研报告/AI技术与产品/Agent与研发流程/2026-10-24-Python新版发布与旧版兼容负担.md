# Python 3.15 发布了，他为什么才开始用 3.11？

Simon Willison｜2026-10-12
原题：Hello Python 3.15, goodbye 3.10, and now I can use 3.11。[1]

Simon 维护的开源项目要兼容所有仍获官方支持的 Python 版本。[1]这篇文章一边介绍 3.15 的新工具，一边解释：对库的维护者来说，旧版退出支持，才让一些早已发布的功能可以放心使用。[1]

## 1. 自己升级，和让所有用户升级，是两回事

文章写道，3.15 发布时，2021 年推出的 3.10 已结束官方支持。[1]按 Simon 的维护政策，他可以停止兼容 3.10，把项目最低版本提高到 3.11；这不意味着项目开始要求用户安装 3.15，也不是所有开发者都必须采取这种政策。[1]

## 2. 插件装多了，连启动命令都要等几秒

他的 LLM 命令行工具支持插件。[1]某些插件依赖 sentence_transformers 这类较重的库，仅仅安装插件，就可能让每次运行命令多等几秒；此前，他在文档里建议插件作者手动延迟加载。[1]

3.15 的显式延迟导入允许写 `lazy import json`，等程序第一次使用相关名称时再加载模块。[1]它针对的是启动时提前加载依赖的开销，不代表后续所有计算都会加速。[1]

## 3. 合并嵌套数据，写法变短了

新语法 `[*sublist for sublist in lists]` 可以把多个子列表展开成一个列表。[1]原文还展示了集合合并、字典合并：集合中的重复值只保留一份，字典遇到重复键时保留后面的值。[1]这是已有展开语法在推导式中的延伸，文章没有把它说成性能优化。[1]

## 4. 想知道程序慢在哪，可以直接观察运行中的进程

新增的 Tachyon 采样分析器会定期记录程序正在执行哪些函数，据此判断时间主要花在哪里。[1]它开销低，不必先往程序里加入测量代码；Simon 以前借助 py-spy，如今标准库提供了这类能力。[1]

新工具叫 `profiling.sampling`；原有的追踪分析器 cProfile 则更名为 `profiling.tracing`。[1]采样工具可连接已有的 Python 3.15 进程，Simon 在 macOS 上需要使用 sudo；除了终端报告，还能生成火焰图、热力图，以及 Firefox 性能分析界面可读取的数据。[1]

## 5. 新版不等于所有程序都明显变快

文章转述 Miguel Grinberg 对 **3.15.0rc3** 的测试：多数表现与 3.14 接近。[1]例外是实验性的 JIT，即运行时把部分代码编译后执行的机制；在斐波那契测试中，其速度达到标准 3.15 解释器的 **1.2 倍**。[1]

这里的基线是标准 3.15 解释器，不是 3.14；结果也只针对该测试，不能当成正式版对所有程序的普遍增益。[1]文中还对比说，Miguel 此前测试 3.14 时，在更多类别上观察到了相对 3.13 的明显提升。[1]

## 6. 切换默认版本，不会自动迁走所有工具

Simon 在 Mac 上先执行 `uv self update`，让 uv 认识新版本，再用 `uv python install 3.15` 安装，用 `uv python pin --global 3.15` 设置以后 `uv run` 的默认版本；项目自己固定的版本仍然优先。[1]

此前通过 uv 安装的工具还要单独迁移。[1]他以 `uv tool upgrade datasette --python 3.15` 为例，随后检查工具实际使用的版本。[1]

## 7. 解除旧版兼容负担，能删掉一些绕行代码

把最低版本提高到 3.11 后，他终于可以依赖内置的 TOML 配置读取库 tomllib；大量使用异步任务的 Datasette，也能采用管理一组任务的 TaskGroup 和控制超时的 timeout()。[1]3.11 还提供 UTC 时区别名和多项类型标注改进。[1]

SQLite 接口的变化更具体：可以读取和设置运行限制，用 Python 编写自定义窗口函数，局部读写数据库里的大型二进制值，以及用 `set_authorizer(None)` 撤销授权检查器。[1]最后一项让 Datasette 原先为兼容旧版准备的绕行实现可以删除。[1]

写作时，他已发起删除该绕行代码的 PR，并更新四个项目模板，使其测试覆盖 3.11—3.15；其他利用 3.11 能力的改进仍计划在随后几周完成，并非已经全部落地。[1]
