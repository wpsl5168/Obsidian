# 让 Agent 会用你的工具：先把命令行帮助做好

Geoffrey Huntley｜个人博客｜2026-10-09。[1]

原文《--help on your CLI is all you need for LLM context until you don't.》讨论：让 AI 操作一款开发工具，是否一定要配置 MCP——一种让模型连接外部工具的接口？作者从模型对工具有多熟悉出发，提出从命令行帮助、在线文档到模型训练的接入路径。[1]

## 1. 模型已经会用的工具，起点不同

作者以 GitHub 为例：如果模型在训练中已经学会它的使用方式，就可以直接调用 CLI，也就是命令行程序，不必额外装技能包或配置 MCP。[1]

他给出的提示示例很具体：让模型使用 GH cli 创建仓库、提交改动、推送到 origin、把仓库设为公开，再更新仓库描述。[1]

## 2. 新工具要先解决“模型不认识我”

新厂商的产品可能还没进入模型的训练知识，用户需要另外安装技能包，甚至先安装 CLI，才能让模型操作它；作者把这些额外步骤视为使用阻力。[1]

他用 S-tier、F-tier 区分两种处境：模型已经熟悉的工具，与还要临时补使用知识的工具；这是作者提出的分法，不是功能或质量排行榜。[1]

## 3. 用任务检验 `--help`，而不只检查文字写得好不好

作者建议先做一个好用的 CLI，再反复优化 `--help`，即程序自带的使用说明。[1] 具体测试是：模型能否逐层查看主命令和各子命令的帮助，找到用法并完成任务。[1]

接着调整说明措辞，以完成任务所需的工具调用次数尽量少为目标；测试、改写、再测试的过程可以自动循环执行。[1] 衡量对象是模型实际做成了什么，不只是人读说明时觉得是否清楚。[1]

## 4. 帮助说明之外，还要让 Agent 搜得到答案

CLI 有了基础后，下一步是把文档放到网上，针对 Agent 的搜索过程优化；文中称为 ASEO，指让 Agent 更容易通过搜索取得所需资料。[1]

作者要求观察单个 Agent 查资料的完整过程，目标是一次搜索就取得完成任务所需的信息，而不是打开文档后继续逐页寻找。[1]

## 5. 更进一步，让工具知识进入模型训练

作者最后建议与模型实验室建立商业联系，争取把 CLI 文档纳入下一轮训练；如果已有推理服务合同，可以从现有合作关系入手。[1]

整条路径追求的是减少用户额外安装技能包、配置 MCP 的负担，基础仍然是一个可用的 CLI。[1] 文中给出的是作者的接入建议，没有提供量化对照实验或与实验室合作后的效果数据；模型熟悉 GitHub 的例子，也不等于所有工具都不需要 MCP。[1]
