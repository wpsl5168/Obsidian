# 用交互式解释理解 Agent 写出的代码

原文：Interactive explanations
作者：Simon Willison｜《Agentic Engineering Patterns》章节

Agent 写出了能运行的代码，人却未必理解它如何工作。Simon 用一个词云生成器的例子，介绍自己如何从阅读代码导读，转向用可暂停、可逐帧播放的动画理解算法。[1]

## 1. 代码不理解，会形成“认知债务”

作者把跟不上 Agent 所写代码的工作原理称为 cognitive debt（认知债务），但没有要求对所有实现细节一视同仁：像从数据库取数再输出 JSON 的简单功能，试用一下、浏览代码确认，往往就够了。[1]

问题出在应用的核心逻辑变成黑箱。按他的说法，开发者无法有把握地推理其行为，规划新功能也会更困难，最终像积累技术债一样拖慢进度；改善对代码的理解，是偿还这笔债的方式。[1]

## 2. 做出词云，不等于理解词云

受 Max Woolf 用 Rust 词云任务测试模型的文章启发，Simon 让 Claude Code 网页版开展研究，做出了能生成词云图片的 Rust 命令行工具。[1]

工具能工作，但报告里的算法说明没有让他明白布局过程：它使用“阿基米德螺线放置”，并为每个词加入随机角度偏移，让布局显得自然。[1]

## 3. 代码导读解决了一部分问题

他随后要求 Agent 按顺序讲解代码库。这样的 linear walkthrough 帮他看懂了 Rust 代码的结构，却仍未建立起对螺线放置过程的直观认识。[1]

于是，他把已有的 walkthrough.md 链接交给另一个 Claude Code 会话，要求先读完整文档，再据此制作动画解释。[1]

## 4. 把“解释算法”写成具体的交互要求

他的提示词要求生成一个 HTML 页面：用户粘贴文本后，页面按导读中描述的算法逐步生成词云；输入保存在 URL 的 #fragment 中，再次打开带有该片段的地址时，自动读取并提交文本。[1]

动画还要提供滑块、暂停和调速功能，暂停后可以逐帧查看，并能在任意阶段把当前词云下载为 PNG。这次使用的模型是 Claude Opus 4.6，文章同时给出了可操作的成品和 GIF 演示。[1]

## 5. 动画展示了文字说明没有讲直观的过程

动画为待放置的词显示一个方框，检查它是否与已有词重叠；如果重叠，就继续尝试位置，沿螺线从中心向外移动，直到找到合适的位置。[1]

Simon 说，看到这个过程后，他才真正理解了算法怎样运行。他最后提出，好的 coding agent 可以按需制作这样的动画与交互界面，既解释它自己写的代码，也解释别人写的代码。[1]
