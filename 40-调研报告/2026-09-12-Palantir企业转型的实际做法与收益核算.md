# Palantir 企业转型：从发现问题到执行决策

## 结论

有官方细节，而且 Centrus 不止一份新闻稿。其高管 Patrick Brown 在 AIPCon 9 展示了项目管控、缺陷分析、人员调配、替换供应商、人工审批与业务系统回写的流程。最有借鉴价值的不是“AI 发现3亿美元”，而是把跨部门决策从电话、邮件、Excel 搬进可执行、可追溯的业务流程。

**证据更新**：初次核查主要依据联合公告；进一步取得 Centrus 官方 LinkedIn 视频的完整 transcript，补充了真实公开的工作流细节。不能再笼统说“官方没有落地细节”。但公众号的30%经理时间、18个月基线、四家监管自动报表、跨密级技术拓扑，以及3亿美元逐项测算，仍没有在这些材料中得到支持。

## 一、Centrus 具体改了什么

以下来自企业高管的公开演讲与展示，不是独立审计，也不能把单次展示指标外推为所有项目的平均收益。[S1][S2]

### 1. 先把进度、成本和人力放到同一工作视图

原来：进度一个系统、成本另一个系统、人力数据又在别处；大量员工手工拼数据。Brown 表示进度数据有时落后8周。

首个落地场景：Project Controls Command Center（项目管控中心），随后介绍 Centrifuge Mission Control（离心机任务管控视图）。统一连接站点、离心机与任务，让建造进度、供应商风险和人员约束持续更新，覆盖 Oak Ridge 制造与 Piketon 运营。[S1]

这里的“实时”是演讲者的产品效果描述，没有公布同步延迟、数据完整率或服务等级指标，不能改写成“跨密级零延迟”。

### 2. 外壳材料缺陷 → 调整人员安排

演讲中的流程：[S1]

1. Agent 发现材料外壳缺陷造成的计划延迟。
2. 生成根因分析，识别成本与进度影响。
3. 在员工、供应商、库存、偏差等关联信息上评估人员重新分配方案。
4. 人工查看、必要时调整、批准。
5. 批准后回写业务系统，更新排班、薪资相关系统，并自动通知现场主管。

Brown 称原本需要多轮电话、邮件和人工分析的过程可以在几分钟内完成。这里公开的是流程和客户自述，不是模型诊断准确率测试。

### 3. 轴承到货质量失败 → 换供应商、加急替换订单

演讲中的第二个例子：[S1]

- 发现轴承货物质量不合格，可能造成数周甚至一个月延迟。
- Agent 比较成本与工期取舍，寻找替代方案。
- 推荐更换供应商并加急替换订单。
- 人工审核接受后执行；展示例子中的 shipment time 从3周缩到1周。

这说明降本增效不一定是“买得最便宜”，而是用可控的采购或物流增加成本，避免更大的停工、等待和延期损失。后一句是分析归纳，不是 Centrus 公布的财务测算。

### 4. 核心护栏：人工拍板、动作留痕

Brown 明确表示 NRC 对 Agent 自主控制并不放心，人的决策和 AI 动作均需记录与追溯。演讲的人员调配和供应商切换均保留人工批准。[S1]

不能从“记录全部动作”推出“完整暴露模型内部推理过程”“满足所有监管要求”或“任意动作都能回滚”。

### 仍未公开的部分

- 近3亿美元潜在节省分别来自哪些工作包、什么基线、哪段时间。
- 多少已经兑现，多少是避免未来支出的估算。
- Palantir 许可费、实施费、内部投入和后续运维成本。
- 各 Agent 的模型、Prompt、算法、优化约束、测试集和错误率。
- 系统数据模型、接口定义、涉密部署拓扑、事故恢复策略。

联合公告仍只支持“identified nearly $300 million in potential cost savings and efficiencies”，不是独立审计的净收益。[S3]

## 二、技术链路：不是多一个聊天机器人

以下为对已核官方能力和案例的综合解释，不是 Centrus 内部架构图。

**业务事件 → 关联业务对象 → 分析可选行动 → 权限/规则校验 → 人工批准 → 执行并回写 → 对账与效果追踪。**

- 数据集成：把 ERP、制造、采购、人事等相关记录连接起来，而不是默认重建全部源系统。
- Ontology：在任务、员工、设备、供应商等实体之间建立统一含义和关系，让“这批货延迟影响哪项任务、谁负责”成为可查询的业务问题。
- 计算与 AI：规则、预测、优化模型和 LLM 分工。排程、约束检查和财务计算不应仅靠 LLM 自由生成；LLM 可协助读取非结构化记录、组织分析、调用受控工具。
- Action：官方文档支持一次动作更新多个对象、属性和关系，并配置校验、权限与通知。[S4]
- 回写：通过 webhook 调用 SAP、Salesforce 或配置的 HTTP 服务，让批准的决策进入源系统。[S5]
- 学习与反馈：记录采用/拒绝建议的原因和执行结果，改规则、模型或应用；不能未经证据声称系统自动在线训练模型权重。

### 重要工程边界

官方文档明确：writeback webhook 先执行外部请求，失败则不修改 Ontology；但**外部成功、Ontology 更新失败仍可能发生**。side-effect webhook 甚至可能在界面提示成功后才执行。[S5]

所以真实交付仍需要幂等键、状态机、失败队列、对账和补偿方案。这些是本报告建议，不是平台自动保障的分布式事务能力。

## 三、其他官方案例能补充什么

### Panasonic Energy：把设备维修经验交到现场技师手里

Palantir 官方案例页披露：Ask Atom 综合历史维修记录、设备传感器数据和非结构化文件，为维修技师提供建议，并将实际解决步骤写回。客户维护经理称培训学习曲线从3—6个月缩到几周。[S6]

可借鉴：把“找资料、问老师傅、试错、记经验”连接起来。应验收首次修复率、平均修复时间、重复故障率和新人独立处理比例，而非只统计问答次数。上述验收项为本报告建议。

### Heineken USA：缺货预警联动供应链调整

官方案例页披露：整合酒厂、仓库、客户数据及船舶监测，提前发现供应链中断，预测缺货并调整交付安排；页面列出490万美元缺货预防价值。[S6]

边界：页面未给出完整审计口径，不能将“value unlocked”直接记成净利润。适合借鉴的是提前预警后如何改变配货，而不是照搬金额。

### Lear：跨部门制造转型，不把整个项目的收益都归给 AI

Lear 官网2025年9月4日公告披露：Foundry/AIP 用于关税风险、行政流程自动化和动态产线平衡，连接质量、供应链、采购、制造、财务与设计。IDEA 转型计划在2025年上半年实现逾3000万美元节省，Palantir 是其中的重要组成部分。[S7]

这是客户官网自述，但**3000万美元属于 IDEA 整体计划，不能全部归因于 Palantir 或 LLM**。

## 四、如果我们帮客户做，应怎样落地

本节是结合案例提出的交付建议，不是 Palantir 的完整官方 SOP，不承诺固定工期或固定收益。

### 第一步：找一个需要改变的业务决策

不要从“建设企业级 AI 平台”开始。先选一条高频、有责任人、有历史数据、能够执行动作的决策，例如：缺货怎么补、异常发票怎么处理、设备故障怎么派单。

写清：谁在什么事件下做决定？今天查哪些系统？最耗时的等待是什么？做错一次损失什么？哪类动作必须人工批准？

### 第二步：建立收益基线

至少有历史事件、处理时间、失败/返工、真实支出、责任部门和质量护栏。记录季节、订单量、品类等差异，避免把业务下滑或结构变化算成系统贡献。

### 第三步：只连这一条流程必需的数据

先解决主键匹配、时间戳、状态含义、数据权限、缺失值和同步频率，不要求全公司数据治理完成后才开始。每个数据字段和业务指标都要有人负责。

### 第四步：先只给建议，再开放受控执行

先回放历史事件，再用影子模式与人工结果对照；达到约定门槛后，开放人工批准下的写回。涉及资金、核安全、合同、人员权益的动作保留适当审批。

### 第五步：业务负责人验效果，财务负责人验金额

- 技术：权限、接口失败、重复执行、异常恢复是否通过。
- 业务：是否减少等待、返工、停机或漏单；是否真的被使用。
- 财务：收益对应哪张单据、哪项支出或哪笔毛利；所有成本有没有扣除。

### 第六步：闭环有效后才复制到相邻流程

复用数据实体、权限、接口和动作。业务专家与工程师持续联合迭代，培训用户，修改岗位 SOP 与责任划分。没有流程负责人和跨部门授权，软件只能生成另一份看板。

Palantir 官方 Bootcamp 主张用1—5天形成初始用例，使用真实问题、训练用户、建立专家反馈，并用实践验证架构。[S8][S9] **这不是五天完成整个企业转型，更不是五天完成收益审计。**

## 五、钱到底怎样算

以下为建议口径，不是 Centrus 官方测算。

- **实际现金降本**：采购、外包、加急费、能耗等真实支出减少，必须有可比基线与单据。
- **容量释放**：员工少花时间是能力释放；除非减少加班、外包、招聘或将时间用于可验证增产，否则不能直接当成现金节省。
- **营运资金释放**：库存减少可释放现金，但不能把全部库存金额当年度利润；持续利润贡献主要体现在资金、仓储、报废等成本变化。
- **增收**：避免缺货或增加产出，要核验新增销售及贡献毛利，不能用销售额冒充利润。
- **避免未来损失**：延期和停机规避依赖反事实估算，应单列，标明假设，不与已实现降本混合。
- **项目成本**：软件许可、实施集成、数据治理、模型/算力、运维、业务专家投入、培训变更和失败补救。

财务净收益应按财务部门确认口径计算；各类别分账，避免同一次停机改善在工时、产量和收入中重复记功。

## 六、对我们做企业咨询的意义

更适合出售的交付是“一条业务流程的改造与持续运营”，而不是“一个知识库或一个 Agent”。

对已有 M365/SharePoint 的客户，可优先验证发票例外处理、合同资料齐套、供应商准入、工单流转等流程；但这只是候选场景，不代表这类办公流程有 Centrus 同等收益空间。是否用 Palantir、微软现有平台扩展或轻量自建，应等流程复杂度、部署要求、采购资格、许可与预算明确后再选，不能从大客户故事直接得出采购结论。
